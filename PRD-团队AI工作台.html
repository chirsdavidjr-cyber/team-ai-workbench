1. 背景与目标

1.1 背景与问题

团队的日常高频工作——意图分析、坐席能力评估、培训、文案、行研咨询、数据日报——目前分散在多个 AI 对话框、Excel 和个人笔记（Obsidian）中，存在以下可观察到的问题：

  • 经验不可复用：成员各自调试有效的提示词、分析口径，无法沉淀给团队；同事重复走弯路。
  • 知识与数据孤岛：业务知识在个人笔记里，业务数据在 Excel 里，AI 无法统一挂载利用，每次问答都要手工贴上下文。
  • 批量工作无任务化承载：批量意图识别、周期性日报等长耗时工作只能靠人工盯着对话框完成，进度与结果无法管理。
  • 模型与 Key 各自为政：模型账号分散采购，无法按人管控与核算成本。

1.2 产品决策

建设一个 Web 形态的团队 AI 工作台（harness 类产品，参照 Trae / WorkBuddy 的交互形态）：统一接入可配置的模型（国产 API 优先，预留国外模型接入），以知识库与数据库为地基，把可复用的提示词与资源组合封装为团队工具库，并以任务系统承载批量与定时工作。

1.3 目标（可观察结果）

  • 成员在一个页面内完成：选择模型对话、上传文档后获得带引用出处的回答、上传 Excel 后用自然语言问数并获得图表与 SQL 溯源。
  • 一个好用的提示词组合可以封装成工具，经审核后被全团队成员一键使用，且使用者能看到使用次数与版本变更。
  • 知识从个人库进入团队库前，必经 AI 预审 + 管理员终审；敏感个人信息在入库前被标记出来。
  • 管理员可以看到按人、按工具、按模型的用量，成员在限额内使用。

2. 范围与分期

2.1 进入条件

系统在单机环境部署完成后，管理员初始化团队并创建成员账号；成员通过浏览器登录。

2.2 P0 —— 首个可用版本（最小完整旅程）

能力说明
账号与空间注册登录、个人空间 / 团队空间、管理员与成员两种角色
首页与对话多模型切换、流式回答、会话管理、对话内挂载资源（FR-HOME）
知识库 v1Markdown / zip 上传、索引、带引用问答、个人库→团队库审核（FR-KB 核心项）
数据库 v1Excel 上传落表、数据画像、语义层 AI 草稿、问数出表格与图表、查询审计（FR-DB 核心项）
模型接入配置国产模型供应商与 API Key（OpenAI 兼容接口），预留国外模型配置位（FR-ADMIN-03）

P0 完成证据：一名新成员注册后，无需培训即可完成——① 选一个模型发起对话并获得流式回答；② 上传一份文档并向它提问，得到带引用出处的回答；③ 上传一份 Excel，用自然语言得到图表、可展开查看 SQL；管理员完成一次知识入库审核、看到一次用量统计。

P0 关键恢复路径：上传失败（格式不支持 / 超限）给出明确原因并允许重试；问数 SQL 执行失败时展示原因与修正建议；模型调用超时或限额时可一键重发。

2.3 P1 —— 团队化

  • 工具库（应用壳、发布审核、版本管理、使用统计）P1
  • 异步任务中心（批量任务、进度、导出、失败重试）P1
  • 我的工作台（推荐版 + 自定义卡片）与待办P1
  • 语义层编辑器（人工确认修订 AI 草稿）P1
  • 完整审核流（知识 / 工具 / 数据集统一队列）P1

2.4 P2 —— 增值能力

  • 知识图谱：利用 Obsidian 双链关系增强检索与可视化P2
  • 定时任务与推送（日报类工具定时执行并推送到协作平台，渠道 TBD）P2
  • 外部数据库只读接入（MySQL / PostgreSQL Assumption）P2
  • 成本看板、工具市场（评分、收藏）、本地 Obsidian 文件夹直连P2

2.5 明确排除（避免分歧）

  • 不做原生移动 App，移动端以响应式网页满足轻量查看 Assumption
  • 不内置模型训练 / 微调能力
  • 不做多人实时协同编辑（同一文档同时编辑）
  • P0 不做外部数据库直连与定时推送

3. 产品模型：角色、对象与状态

3.1 角色与权限总览

角色说明核心权限差异
管理员初始化团队者默认为管理员，可指定其他管理员 Assumption；建议 ≥1 名成员管理、统一审核（终审）、模型与 Key 配置、用量与审计查看、团队资源删除
成员普通使用者个人空间全部权限；团队资源的查看与使用；发起入库 / 发布申请

详细的模块级权限矩阵见 第 5.1 节（唯一定义处）。

3.2 核心对象与生命周期

对象定义状态流转
会话一次对话的载体；从工具进入的会话自动携带工具配置进行中 → 已归档；已删除（回收站 Assumption: 30 天）
工具（应用）可复用的能力封装 = 系统提示词 + 绑定资源（0..n 知识库 / 数据集）+ 开场白与推荐问题 + 输出模板 + 默认模型草稿 → 待审 → 已发布 ⇄ 已下线；待审 → 已驳回 →（修改）→ 待审
知识文档个人库或团队库中的一篇 Markdown 文档（保留目录结构与双链关系）处理中 → 可用；待审 → 已入团队库 / 已驳回；可用 → 已归档
数据集一次 Excel 上传落成的结构化表（个人 / 团队）处理中 → 可用；待更新（源文件重新上传）
语义层附属于数据集的业务描述集：表 / 字段含义、枚举值翻译、表间关系、指标口径AI 草稿 → 已确认（人工修订后）；每次变更留版本记录
异步任务批量或定时执行的工作单元（P1 起）排队中 → 运行中 → 成功 / 失败 / 已取消；失败 → 重试
待办手动创建或 AI 从对话中提取并经用户确认的事项未完成 → 已完成；可设截止时间

3.3 空间与可见性规则

  • 个人空间默认仅本人与管理员不可见——管理员也不可查看成员个人库内容，仅可见其用量 Assumption；团队空间全员可见。
  • 引用方向约束：个人工具可绑定团队资源；团队工具只能绑定团队资源（防止团队工具因个人资源被删而失效）。
  • 删除团队资源需管理员操作；删除产生回收站记录，期限内可恢复。

目的与布局

首页是成员的默认工作入口。布局三区：左侧边栏（首页、我的工作台、工具库、知识库、数据库、任务中心、会话列表）；中间主区（未对话时显示欢迎语、常用工具卡与输入框；对话后在主区展开对话流）；右侧展示区（对话开始后出现，展示引用来源、图表、任务进度等结构化结果）。

M2 工具库 P1

目的

把「提示词 + 资源绑定」的可复用组合封装为工具，是团队经验沉淀的核心载体。工具的地基是知识库与数据库：意图分析工具绑定意图标注规范文档，问数工具绑定渠道指标数据集，以此类推。

编号能力需求描述
FR-TOOL-01工具库视图两个分组：团队工具（已发布，全员可见）与我的工具（本人草稿与已发布）。支持分类标签筛选（意图分析、坐席能力评估、培训、文案、行研、日报、问数…标签由管理员维护）与关键词搜索。
FR-TOOL-02创建工具（应用壳）表单字段：名称（必填，≤30字）、图标（可选，默认生成）、描述与适用场景（必填，≤200字）、系统提示词（必填）、绑定资源（0..n 知识库引用 + 0..n 数据集引用，受 3.3 引用方向约束）、开场白与推荐问题（可选）、输出模板（自由文本 / 表格 / JSON Assumption，默认自由文本）、默认模型。保存即草稿，草稿可立即自测。
FR-TOOL-03使用工具从工具卡或工具详情页进入即创建携带配置的会话；会话头部展示工具名与绑定资源，可「转为普通对话」（解除绑定）。
FR-TOOL-04发布到团队提交发布 → AI 预审（见 5.2 统一审核流：描述完整性、提示词可执行性、绑定资源有效性、敏感扫描）→ 管理员终审通过后进入团队工具列表。驳回理由必填并通知创建人。
FR-TOOL-05版本管理已发布工具的修改保存为新版本（v2、v3…），发布同样走审核；版本切换对使用者透明，但工具卡片显示「已更新至 vN」，使用者可选择继续用旧版直到下次新会话 Assumption。支持回滚到历史版本（同样走审核）。
FR-TOOL-06工具信息卡展示：创建人、版本号与更新时间、绑定资源、使用次数、收藏数、（P2）评分。绑定资源被删除或下线时，工具卡片标记「资源失效」，进入会话时提示创建人修复。

M3 知识库 P0

目的与形态

以 Obsidian 的使用心智组织团队知识：知识 = 一棵 Markdown 文档树，保留目录结构与 [[双链]]。个人库私有，团队库经审核共享。回答必须带引用。

编号能力需求描述
FR-KB-01库结构每人生成一个个人库；一个团队库，内按主题文件夹组织（文件夹由管理员与成员共同维护，移动文档不改变引用）。列表视图 = 目录树 + 文档列表；文档预览支持渲染 Markdown 与双链跳转。
FR-KB-02上传支持单个 / 批量 .md 与 .zip（保留内部目录结构）。上传 Obsidian 整库 zip 时自动忽略 .obsidian 等配置目录 Assumption: 首版 zip 上传；文件夹拖拽上传 P1；Git 同步 P2。单文件与整库大小限额 TBD。同名同路径文档上传时询问「替换或另存」。
FR-KB-03处理管道上传后自动：解析 → 切块 → 向量化 → 建索引。处理中文档状态为「处理中」、不可被检索；处理失败（如加密 zip、损坏文件）标红并允许重试或删除。处理完成人数在文档列表可见。
FR-KB-04双链保留解析 [[双链]] 与标签存储为文档关联关系；P0 仅存储与列表展示「被 n 篇引用」，P2 用于图谱可视化与检索增强。
FR-KB-05检索问答对挂载 / 绑定的库做检索增强回答；检索策略为混合检索（向量 + 关键词）。回答带引用角标（FR-HOME-05）；无命中时明确说明，不得编造。
FR-KB-06入库审核个人库文档「申请入团队库」→ AI 预审（查重、质量评估、敏感信息扫描，见 5.2）→ 管理员终审。通过后文档进入团队库指定文件夹；驳回附理由。演示见下方。
FR-KB-07知识管理文档可预览、替换更新（重新走索引）、归档、删除。团队库删除需管理员；删除进回收站可恢复（3.3 规则）。
FR-KB-08对话沉淀任意会话可「保存为知识」：AI 将该轮问答整理为 Markdown 草稿存入个人库，状态为「草稿」，必须本人确认后才可被检索与申请入库。

M4 数据库与问数 P0

目的

让成员把 Excel 变成「可对话的数据集」：上传即建表，语义层让 AI 看懂字段业务含义，问数输出表格 / 图表 + SQL 溯源 + 解读诊断。语义层的质量决定问数准确率，因此语义层是本模块第一公民。

编号能力需求描述
FR-DB-01数据集创建上传 .xlsx / .csv Assumption（单表 Sheet，多 Sheet 时逐个选择 Assumption）→ 自动落表 → 自动生成数据画像：行数、列清单、类型推断、空值率、每列样本值。画像随数据集展示，是语义层生成的输入。
FR-DB-02语义层落表后 AI 生成语义层草稿：每表 / 每字段的业务含义、枚举值翻译（如 status=1 → 待处理）、表间关系、常用指标口径（如「接通率 = 接通量/呼入量」）。P0 以草稿生效 + 问数对话中修正；P1 提供编辑器人工确认修订，修订记录版本。数据集更新（重新上传）后提示「语义层可能需要更新」并高亮结构差异。
FR-DB-03问数自然语言 → 检索相关表与语义定义 → 生成 SQL → 只读沙箱执行 → 表格 / 图表展示（图表类型由 AI 按数据形态选择，可手动切换）→ 支持基于上轮结果的追问。回答默认折叠展示所用 SQL 与引用的语义定义，点击展开。演示见下方。

5.2 统一审核流（知识 / 工具 / 数据集共用，唯一定义处）

  1. 发起：成员对个人资源提交「入团队 / 发布」申请。
  2. AI 预审（自动，即时完成），四项检查：
    • 查重：与团队库已有内容的相似度；高相似（阈值 TBD）标记并展示比对结果，不自动拦截；
    • 质量评估：完整性、结构（附建议，不阻断）；
    • 敏感信息扫描：手机号、身份证号、银行卡号等模式 Assumption: 首版规则库，命中处高亮展示，由人工判断；
    • 资源有效性（工具专属）：绑定资源是否存在、提示词是否为空。
  3. 管理员终审：查看预审结果与内容原文，通过或驳回（驳回理由必填，系统通知提交人）。
  4. 通过后：进入团队空间并即时对全员可见；提交人收到通知。
  5. 重新提交：被驳回资源修改后可再次提交，保留历史审核记录。

5.3 删除与恢复

  • 所有对象删除进入回收站，保留 Assumption: 30 天；期限内可恢复，期满彻底清除。
  • 被其他对象引用的资源（工具绑定的知识 / 数据集）删除时，提示影响范围（哪些工具会失效），团队资源需管理员确认。

5.4 成本规则

  • 团队 Key 用量计入配额；BYOK 用量不计入（FR-ADMIN-03）。
  • 配额展示：成员可在个人设置看到自己的用量与剩余额度；超额策略 TBD（提醒或限制）。
  • 批量任务预估：创建批量任务时展示预估 Token 消耗，超配额时需二次确认 Assumption。
