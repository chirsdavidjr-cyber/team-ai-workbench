# 工具库页面全面改造说明

> 改造日期：2026-11-21
> 参考基准：知识库（kb）模块的设计规范、交互模式与功能逻辑，并与其数据库规则（`KbDoc.path` / `KbFolder` / `Dataset.folder` / `DatasetFolder` / `Dataset.team_status` 审核流）完全对齐。
> 兼容性原则：**全部为增量式改造**，旧 API 接口、字段与默认行为保持不变，首页工具卡、对话页工具选择器、对话「沉淀为工具」、批量任务、Agent 函数调用（`list_tools`/`create_tool`/`update_tool`/`delete_tool`）等既有消费方零改动。

## 二、数据库结构变更与对应关系

### 2.1 `tools` 表（增量列，SQLite 轻量迁移）

| 新列 | 类型 | 默认 | 对齐的知识库/数据模块规则 |
|---|---|---|---|
| `folder` | `VARCHAR(512)`，索引 | `""` | 与 `kb_docs.path`（目录结构）、`datasets.folder`（分组路径）同构，支持 `/` 多级分组 |
| `team_status` | `VARCHAR(16)`，索引 | `""` | 与 `datasets.team_status` 完全同构：`""`（未申请）/ `pending` / `approved` / `rejected` |

**迁移逻辑**（`main.py::_migrate`，幂等）：
1. `ALTER TABLE tools ADD COLUMN folder TEXT NOT NULL DEFAULT ''`；
2. 存量回填：`UPDATE tools SET folder = category WHERE folder = '' AND category != ''` —— 旧工具按原分类直接进入分组树，无数据丢失、无需人工整理；
3. `ALTER TABLE tools ADD COLUMN team_status TEXT NOT NULL DEFAULT ''`。

### 2.2 新表 `tool_folders`（空分组占位）

与 `dataset_folders` / `kb_folders` 完全同构：`id / owner_id / scope / path / sort / created_at`。
规则一致：有工具的分组由工具 `folder` 前缀动态聚合生成，空分组由该表占位；个人分组按 `owner_id` 隔离，团队分组仅管理员可建。

## 三、后端接口变更（`/api/tools`）

### 3.1 保持向下兼容（未改动行为）

| 接口 | 说明 |
|---|---|
| `GET /api/tools` | 默认 `scope=all`（团队 + 本人个人），默认排序 `use_count desc, id desc`，与旧版一致；响应仅**新增** `folder`、`team_status` 字段（旧消费方忽略即可） |
| `POST /api/tools` | 旧字段全部有效（缺省 `folder=""`）；`scope=team` 仍需管理员（403 逻辑不变） |
| `PUT /api/tools/{id}` | 旧字段全部有效；权限不变（所有者或管理员） |
| `DELETE /api/tools/{id}` | 行为不变 |
| `POST /api/tools/draft-from-conversation` | 完全未改动 |

### 3.2 新增能力

| 接口 | 方法 | 对齐来源 | 说明 |
|---|---|---|---|
| `/api/tools?q=&sort=` | GET 增强 | `kb/docs` 搜索 | `q` 模糊搜索名称/描述/分类/系统提示词；`sort=use(默认)/updated/name` |
| `/api/tools/folders` | GET / POST | `data/folders` | 列出/新建分组占位；团队分组需管理员 |
| `/api/tools/folders` | PATCH / DELETE | `data/folders` | 重命名/移动分组（组内工具与子分组前缀同步改写）；删除仅限空分组（有工具 400、有子分组 400、不存在 404） |
| `/api/tools/{id}/move` | PATCH | `data/datasets/{id}/move` | 移动工具到指定分组（空 = 未分组） |
| `/api/tools/{id}` | GET | `kb/docs/{id}` | 单工具详情（团队全员可见；个人工具仅所有者与管理员） |
| `/api/tools/{id}/request-team` | POST | `data/datasets/{id}/request-team` | 个人工具申请入团队库 → `team_status=pending`；重复申请 400 |
| `/api/tools/{id}/review-team` | POST | `data/datasets/{id}/review-team` | 管理员审核：批准 → `scope=team, team_status=approved`；驳回 → `team_status=rejected`（保留在个人库）；非 pending 404 |
| `/api/tools/team-requests` | GET | `data/team-requests` | 管理员查看待审列表（带 pending 数角标） |

### 3.3 权限校验逻辑适配（与知识库规则对齐）

| 场景 | 旧逻辑 | 新逻辑 |
|---|---|---|
| 成员发团队工具 | 403（保持） | 403（保持），新增正道：`request-team` 审核流 |
| 编辑时调整 scope | 不支持（`ToolUpdateIn` 无 scope） | 支持：转 `team` 需管理员（403 拦截成员），管理员直转视为 `approved` |
| 团队分组操作 | 无分组概念 | 建分组仅管理员可写（403），读取全员（与 kb/data 一致） |
| 单工具可见性 | 无单查接口 | 团队全员可见；个人仅所有者/管理员（404 防枚举） |

> 注意路由注册顺序：`DELETE /folders` 必须先于 `DELETE /{tool_id}` 注册（已修正），否则 `/folders` 会被 `{tool_id}:int` 路径参数截获返回 422。

## 四、前端改造明细

### 4.1 页面布局重构（`tools/page.tsx` 重写）

改造前：单列卡片流（团队/个人两节），无搜索、无分组、无详情页，弹窗编辑。
改造后（与知识库/数据模块同构）：

```
┌─────────────┬──────────────────────────────────────────┐
│ 左：分组树    │ 右：工具栏（库切换/搜索/类型/排序/指引/审核/新建） │
│ 全部工具(N)  │ ──────────────────────────────────────── │
│ 🧰 分组(多级) │ 工具表格（工具/类型/分类/分组/使用/更新/状态/操作）│
│ ＋ 新建 «收起 │   ⇄ 点击行 → 详情原地切换（预览/行内编辑）      │
└─────────────┴──────────────────────────────────────────┘
```

- **库切换**：`我的工具` / `团队工具`（分段控件，同 kb/data）
- **搜索**：300ms 防抖、服务端 `q` 检索（同知识库）
- **排序**：使用最多（默认，与旧版一致）/ 最近更新 / 名称
- **类型筛选**：全部 / Agent / Skill / Template
- **分组树**：多级、展开收起记忆（localStorage `tools-collapsed-{scope}`）、面板整体收起（`tools-tree-hidden`）、⋯ 操作菜单（重命名/移动/删除）
- **深链**：`/tools?scope=team&folder=客服&open=3`（同 data 页）
- **行操作菜单**：打开详情 / 使用工具 / 移动分组 / 申请入团队库（成员本人）/ 删除（所有者或管理员）
- **首次使用指引弹窗**（`tools-guide-seen`）与 **toast（1.5s 自动消失）**：与知识库交互一致
- **新建弹窗**：补齐旧弹窗缺失的「分组」「能力面白名单」字段；管理员可选共享范围（默认跟随当前库）
- **团队审核弹窗**（管理员）：待审列表 + 批准/驳回，工具栏按钮带待审数角标

### 4.2 组件复用

| 新组件 | 复用来源 | 差异点 |
|---|---|---|
| `components/tool-tree.tsx`（`ToolTreePanel`） | `components/data-folder-tree.tsx`（`DataTreePanel`） | 去掉图谱入口（工具库无图谱）；API 指向 `/api/tools/folders`；图标 🧰 |
| `components/tool-detail.tsx`（`ToolDetail`） | `components/kb-detail.tsx`（`KbDetail`） | 正文为系统提示词（等宽块）+ 推荐问题 chips + 能力面展示；行内编辑含能力面/共享范围 |
| `fmtTime` | 直接复用 `kb-detail.tsx` 导出 | — |
| `useAppData().refreshTools / setActiveTool` | 沿用全局上下文 | 任何增删改后同步刷新，首页/对话页工具选择器即时更新（向下兼容关键点） |

### 4.3 数据交互逻辑调整

- 列表加载：`GET /api/tools?scope&q&sort` + `GET /api/tools/folders?scope` 并行请求（同 data 页）
- 分组聚合：工具 `folder` 前缀 ∪ `tool_folders` 占位（同 kb/data 的 folders 聚合算法）
- 所有变更操作后 `load() + refreshTools()` 双刷新，保证页面与全局上下文数据一致

## 六、遗留说明

1. 后端服务已用新代码重启（`uvicorn app.main:app --port 8000`），迁移已自动执行；如在其他环境部署，首次启动自动完成迁移，无需手工操作。
2. `agent.py` 的 AI 工具管理动作（`create_tool` 等）创建的工具 `folder=""`（未分组），用户可在工具库页移动归组——与「成员沉淀默认进未分组」的设计一致。
3. 对话页「沉淀为工具」未传 `folder` 参数，走默认未分组（向下兼容，无需改动）。
