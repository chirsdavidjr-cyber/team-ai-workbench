## 一、最重要的结论：agent 能力已经落地，我之前的评估已过时

这是本次实测最大的纠错。

**第一份报告（10:22）判断**：模型调用未传 `tools`、Tool 只是提示词壳、没有 agent loop，"标准 function calling 自由调用：未做"。

**实测结果（13:20）**：这些全部**已经实现**。`backend/app/agent.py`（31KB）已建立完整 function calling 闭环，`chat.py` 已接入，前端能渲染工具调用卡片。我用成员账号实测了完整流程：

| 实测动作 | 观察到的工具调用 | 结果 |
|---|---|---|
| "查看我的知识库里有哪些文件夹" | `✓ list_kb scope=personal 完成` | 模型先查结构，再回答"个人库是空的" |
| "在我的知识库新建文件夹 测试目录A" | `✓ list_kb` → `✓ kb_create_folder path=测试目录A 完成` | 两轮工具调用，文件夹真建成了 |
| "删除我知识库里的测试目录A" | 无工具调用 | 模型复述"操作对象/范围/说明"，要求回复"确认" |
| 回复"确认" | `✓ kb_delete_folder path=测试目录A 完成` | 真删除，卡片可展开看后端详情 |
| "在团队知识库新建文件夹 越权测试" | `✗ kb_create_folder path=越权测试 scope=team 失败` | 后端拒绝，模型引导正确流程 |

**结论**：第一份报告里的"四动作修复方案"已经被落地，且实现质量相当高——

- 支持工具调用卡片展开看参数与结果（执行透明度好）
- 删除有"复述对象 + 明确确认"二次把关（安全设计到位）
- 权限在工具执行层拦截，模型会给出"先存个人库再申请入团队库"的正确引导
- `WORKBENCH_HINT` 里明确写了"严禁在回复文本中伪造调用过程或结果"，防幻觉

**这个发现意味着**：后续不要再拿第一份报告说"agent 没做"。它现在的作用是"设计说明"，实际代码已经跑通。

## 三、实测新发现的问题（静态评估看不到的）

### 问题一：同一问题两次回答，图表数据自相矛盾（严重度：高）

这是本次实测最有价值的发现，是真实用户已经看到的现象：

- 历史问数记录中"各渠道接通率是多少"出现两次
- 一次图表画的是 3275/3226/3509/3726，AI 文字解读却是"邮件最高 77.19%，APP 最低 67.51%"
- 另一次图表画的是 0.77/0.71/0.70/0.68，与文字一致
- 根因：模型生成的 SQL 列数不固定（2 列 vs 4 列），而 `MiniChart` 永远取第 2 列当数值。SQL 为 4 列时第 2 列是"接通量合计"而非"接通率"

**修复方案（精确版）**：不能只做我第三份报告说的"让用户手选维度/数值列"——那是治标。治本是两条：

1. `text2sql` 的 system prompt 里加硬约束：**"若问题问的是某指标，SELECT 的第一列必须是维度、第二列必须是该指标值；额外辅助列请放到指标列之后"**。
2. `MiniChart` 增加兜底：当 `columns` 里存在名称含"率/占比/比例"的列时，优先选它当数值列，而不是无脑取第 2 列。
3. 前端仍保留手动切换入口作为最终保险。

### 问题二：问数 17.9 秒黑盒等待（严重度：高）

实测数据：一次普通问数 17.9 秒返回。期间前端只有一个转圈，无进度细分、无取消。这和我第三份报告的判断完全一致，且现在有了实测数字。"改流式 + 可取消"的优先级应维持 P0。

### 问题三：知识库使用指引弹窗遮挡（严重度：低）

成员首次进入知识库弹出大尺寸指引，覆盖整页中央，只有一个"开始使用"出口。内容质量很高，但用户若想先看看界面再读指引，找不到跳过方式。建议加右上角关闭按钮，或记住"已读过"状态。

### 问题四：前端 Context 缓存不同步（严重度：低）

删除工具后，任务中心下拉框仍显示已删工具名。建议 `tools` 变更后触发全局 `refreshTools()`。

### 问题五：登录页明文管理员密码（严重度：中）

登录页底部直接显示默认账号密码。内网环境可接受，但结合 `SECRET_KEY` 默认值问题，等于把两道门都虚掩着。建议：首次部署引导页里显示，正常登录后移除；或做成"仅当密码仍是默认值时显示"。
