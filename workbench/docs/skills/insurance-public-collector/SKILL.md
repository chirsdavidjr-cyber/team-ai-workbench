# 公开网页采集与台账（Insurance Public Collector）

## 一句话定位

只对**无需登录的公开网页**做信息采集，抓**完整正文**，产出**可追溯台账**。目的：为公司采集**最新的、有价值的行业信息**——行业动态、监管政策、同业动向、险种信息、医药医保政策，供业务参考使用。用户有其他需求时按通用需求流程处理。

不碰登录态、不碰验证码、不碰隐私字段、不对外发送。

## 范围边界（重要）

本 skill 服务于公司内部信息采集，有两条明确排除：

- **不采本公司（太平洋产险/太保）自有网页**：自己家的公开信息内部已有，采了没有情报价值。站点台账里不登记本公司官网，关键词库里本公司品牌词只作排除项，不作采集目标。
- **不纳入舆情监测**：黑猫投诉这类投诉/舆情站点属于舆情监测范畴，不是"行业最新信息"，暂不写入默认场景。如后续单独做舆情监测，另起 skill 或另配场景。

## 谁该读这份文档

本 skill 面向任意 AI 执行与审视。所有规则、清单、字段、流程均内联在本目录，不依赖外部源码或口头约定。审视者请重点看文末「审视要点」一节。

## 核心原则

1. **公开优先**：只采无需登录即可访问的公开页面。需要登录、验证码、签名、滑块的一律停止并记录，不绕过。
2. **完整正文**：不能只采列表标题。列表页取链接，详情页抓正文全文，原文完整落盘。
3. **条条可溯**：每条数据带来源站点、原文链接、采集时间、关键词、批次号；批次有配方、明细有台账。
4. **默认即场景**：用户没指定需求时，按「默认采集场景」执行，不要反问、不要空跑。
5. **需求可扩展**：用户给出其他采集需求时，按「通用需求处理」映射站点与关键词，确认后执行。
6. **脱敏落盘**：手机号、身份证号、住址、订单号、真实姓名等隐私字段一律不采不存。

## 触发与分流

收到采集需求后先分流，规则如下：

| 情况 | 处理方式 |
| --- | --- |
| 用户只说"采集""跑一下""按默认来" | 直接执行默认采集场景 |
| 用户指定主题/关键词/站点 | 走通用需求处理，确认站点与关键词后执行 |
| 用户明确要社交媒体的登录后内容 | 停止并说明本 skill 只做公开网页，需要登录的另走带登录流程 |
| 用户要实时/高频监控 | 说明公开网页采集的时效边界，建议定时批次，不承诺实时 |

## 默认采集场景

用户未指定需求时的默认执行内容。完整站点清单、栏目地址、关键词清单、优先级见 `references/default-scope.md` 与 `references/keyword-bank.md`。

五大方向：

- **行业信息**：中国保险行业协会、行业新闻与研究报告
- **监管信息**：国家金融监督管理总局的政策法规、公告通知、行政处罚、交强险等公告
- **同业信息**：平安产险、人保产险的公开新闻、公告、产品信息（不含本公司）
- **险种信息**：车险、非车险、健康险相关的政策与市场信息
- **医药医保**：国家药监局、国家医保局的药品目录、创新药、医保支付、健康险创新药目录等

服务对象：中国太平洋产险（内部使用）。采集结果按这五类归档，每类独立台账。只采外部公开信息，不采本公司自有网页。

## 标准工作流

每次采集严格按此顺序，不跳步：

1. **读规则**：先读 `references/compliance.md`，确认合规边界。
2. **定场景**：默认场景读 `references/default-scope.md`；其他需求读 `references/general-request.md`，必要时向用户确认站点与关键词。
3. **查站点**：在 `references/site-registry.md` 找对应站点的栏目入口与抓取方式。新站点先实测可达性再登记。
4. **抓列表**：用 WebFetch 抓列表页，提取标题、日期、详情链接。
5. **抓正文**：逐条打开详情页，抓完整正文。列表与正文都要，不能只留标题。
6. **脱敏**：按合规规则清掉隐私字段。
7. **落盘**：调 `scripts/collect.py` 生成标准条目、原文存档、汇总表。
8. **生成台账**：调 `scripts/ledger.py` 生成批次台账与明细台账，写入配方。
9. **自检**：核对条数、链接可回指、正文完整、台账字段齐全、隐私字段为零。
10. **回报**：按交付规范汇报，不写长报告。

## 工具与脚本

| 文件 | 用途 |
| --- | --- |
| `scripts/fetch_public.js` | 通用公开网页抓取：给列表页 URL 与详情链接选择器，输出条目 JSONL。基于本机 Chrome + playwright-core，无需安装额外工具 |
| `scripts/collect.py` | 落盘：去重、原文存档、汇总 CSV、manifest |
| `scripts/ledger.py` | 台账生成：批次台账、明细台账、配方 |
| `templates/config.default.json` | 默认场景配置：站点、关键词、字段、限速 |
| `templates/ledger_template.csv` | 台账表头模板 |

工具选择：静态公开页优先 WebFetch（最省）；JS 渲染或需要批量翻页时用 `fetch_public.js`。两者都不需要登录。

## 合规硬规则

以下一律不做，无例外：

- 不登录、不代填账号密码、不代扫码、不读取用户已登录浏览器的登录态
- 不破解或伪造签名，不绕过验证码、滑块、登录墙、IP 风控
- 不采隐私字段：手机号、身份证号、住址、真实姓名、私信、非公开群聊、订单号、保单号、客户编号
- 不修改 robots.txt 或服务条款判断去迁就采集
- 不对外发送采集结果，只落本机
- 遵守单站限速：默认每条间隔 ≥2 秒，单站单批 ≤200 条

完整规则见 `references/compliance.md`。

## 通用需求处理

用户提出其他采集需求时：

1. 解析需求：主题、站点范围、关键词、时间范围、字段、数量。
2. 映射到已有站点台账；没有对应站点就先实测可达性，再登记进站点台账。
3. 把用户关键词与 `references/keyword-bank.md` 合并，形成本次配方。
4. 需求含糊时一次问清（站点/关键词/数量），不逐项挤牙膏。
5. 需求涉及登录态或隐私时，明确拒绝该部分，只做公开部分。

详见 `references/general-request.md`。

## 审视要点

给其他 AI 审视时，请按 `references/review-checklist.md` 的清单逐项核对，重点确认：

- 默认场景是否覆盖用户列的全部方向
- 关键词清单是否内联且完整
- 站点台账是否有实测依据、抓取方式是否可执行
- 台账是否做到条条可溯
- 合规边界是否清晰、隐私字段是否为零
- 通用需求流程是否可扩展

发现问题直接改文件，不要只在回复里提。
