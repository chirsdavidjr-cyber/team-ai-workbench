# 交付规范

## 输出目录结构

```
输出根目录/
  采集总台账.csv
  批次/
    YYYYMMDD_方向_序号/
      配方.md
      明细台账.csv
      items.jsonl
      summary.csv
      manifest.json
      原文存档/
        关于2025年度机动车交通事故责任强制保险业务情况的公告.md
        国家医保局关于印发2026年药品目录的通知.md
        ...（文件名即文章标题）
  当前/
    行业_latest.csv
    监管_latest.csv
    同业_latest.csv
    车险_latest.csv
    非车险_latest.csv
    健康险_latest.csv
    药监_latest.csv
    医保_latest.csv
```

## 各文件说明

- `采集总台账.csv`：一行一个批次，看全局采集历史。
- `配方.md`：本批次来路，六段固定格式，见 ledger-spec.md。
- `明细台账.csv`：一行一条内容，条条可溯。
- `items.jsonl`：标准条目，一行一个 JSON。
- `summary.csv`：结构化汇总表，UTF-8 BOM，Excel 直接打开。
- `manifest.json`：批次元信息，含条数、去重、受阻、脱敏标记。
- `原文存档/<文章标题>.md`：每条一个文件，文件名即文章标题（清洗非法字符、限长 60 字、重名加序号），不覆盖；内容含标题、正文全文、链接、来源、时间、命中关键词。
- `当前/<方向>_latest.csv`：该方向最新汇总，覆盖更新。

## 标准条目结构

```json
{
  "source": "站点名",
  "column": "栏目名",
  "url": "详情页链接",
  "title": "标题",
  "content": "正文全文",
  "published_at": "公开时间，拿不到留空",
  "author": "公开署名，拿不到留空",
  "keywords": ["命中的关键词"],
  "direction": "方向",
  "collected_at": "采集时间",
  "extra": {}
}
```

字段拿不到就留空，不猜、不编。

## 原文存档格式

```
# 标题

- 来源：站点 / 栏目
- 链接：详情页 URL
- 发布时间：xxxx
- 作者/署名：xxxx
- 命中关键词：xxx;xxx
- 采集时间：xxxx
- 脱敏：已处理（类型）

## 正文

正文全文，完整保留，不改写、不摘要替代。
```

## 交付给用户的形态

用户要什么给什么，默认给三样：完整原文与链接、结构化汇总表、可追溯台账。

- 用户说"给我表格" → 给当前区 CSV 或本批 summary.csv
- 用户说"要台账" → 给采集总台账 + 明细台账 + 配方
- 用户说"要原文" → 给原文目录
- 用户没说 → 三样都给，但汇报时只用四句话

## 收工回报（四句话）

1. 采了哪些站点、各多少条
2. 输出目录在哪
3. 台账在哪
4. 有没有受阻或异常，原因是什么

不写长报告，不堆过程细节。
