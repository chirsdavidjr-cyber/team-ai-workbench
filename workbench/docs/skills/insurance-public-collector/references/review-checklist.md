## 九、常见审视问题与答案

**问：为什么要拆成独立 skill，不直接改 web-collector？**
答：web-collector 是通用采集框架（含社媒登录态）；本 skill 只做公开网页、带行业默认场景与台账，职责不同，独立更清晰。

**问：默认场景会不会太宽，跑一次很慢？**
答：按方向分批，每批每站 ≤200 条、间隔 ≥2 秒；用户可缩小时间范围或只跑指定方向。

**问：小红书检索算不算进来？**
答：不算。小红书关键词搜索需要登录，本 skill 只做公开网页。公开推荐流虽可读，但不符合"带关键词检索"的需求，故不纳入默认场景。

**问：网页结构变了怎么办？**
答：选择器写在脚本配置里，结构变了先抓快照看新结构，再改选择器，不硬套旧规则。

## 十、审视后动作

审视发现问题时的处理顺序：

1. 需求覆盖问题 → 改 default-scope.md / SKILL.md
2. 关键词缺失 → 改 keyword-bank.md
3. 站点失效 → 改 site-registry.md 并重新实测
4. 合规边界问题 → 改 compliance.md
5. 流程或脚本问题 → 改对应脚本或 SKILL.md 工作流
6. 改完在核对结论处记录，不要只在对话里说
