# 台账规范（条条可溯）

台账的目标：任何一条采集结果，都能追到它来自哪个站点、哪个栏目、用什么关键词、哪次批次、什么时间采的、用了什么配方。

## 台账体系（三层）

1. **采集总台账** `采集总台账.csv`：一行一个批次，看全局。
2. **批次明细台账** `批次/YYYYMMDD_事由/明细台账.csv`：一行一条内容，看细节。
3. **批次配方** `批次/YYYYMMDD_事由/配方.md`：记本批次的站点、关键词、字段、工具、版本、时间组合，看来路。

追溯链：任一结果 → 明细台账 → 批次目录 → 配方.md。

## 采集总台账字段

| 字段 | 说明 |
| --- | --- |
| 批次号 | `YYYYMMDD_方向_序号`，如 `20261120_监管_001` |
| 采集日期 | YYYY-MM-DD HH:MM:SS |
| 方向 | 行业/监管/同业/车险/非车险/健康险/药监/医保/自定义 |
| 站点 | 站点名 |
| 栏目 | 栏目名或栏目 URL |
| 关键词 | 本批使用的关键词，分号分隔 |
| 时间范围 | 用户指定或默认近 30 天 |
| 抓取方式 | WebFetch / fetch_public.js |
| 输入条数 | 列表页拿到的候选条数 |
| 保留条数 | 去重脱敏后落盘条数 |
| 去重条数 | 重复跳过数 |
| 受阻条数 | 因登录/验证码/空正文跳过数 |
| 脱敏 | 是/否 |
| 输出目录 | 批次目录路径 |
| 状态 | 完成/部分完成/受阻/本期无更新 |
| 备注 | 异常情况说明 |

## 批次明细台账字段

| 字段 | 说明 |
| --- | --- |
| 序号 | 批次内顺序，0001 起 |
| 批次号 | 关联总台账 |
| 方向 | 所属方向 |
| 站点 | 来源站点 |
| 栏目 | 来源栏目 |
| 标题 | 公开标题 |
| 发布时间 | 页面公开时间，拿不到留空不猜 |
| 作者/来源署名 | 公开署名，机构可留个人非公开姓名不留 |
| 原文链接 | 详情页 URL，必须可回指 |
| 命中关键词 | 命中的关键词，分号分隔 |
| 正文摘要 | 正文前 200 字，完整正文见原文存档 |
| 正文字数 | 便于核对完整性 |
| 脱敏标记 | 是/已脱敏，记录处理过的类型 |
| 采集时间 | YYYY-MM-DD HH:MM:SS |
| 本地存档 | 原文存档相对路径，文件名即文章标题（非编号），取自条目的 archive_file 字段 |

## 配方.md 内容

每批次一份，固定六段：

```
批次号：
采集方向：
站点与栏目：（逐条列 URL）
关键词：（本次全部关键词）
字段：（本次提取的字段清单）
工具与版本：（WebFetch / fetch_public.js 版本号）
时间与限速：（采集起止时间、间隔秒数、单批上限）
备注：（异常情况、用户特殊要求）
```

## 当前区与批次区

- `批次/`：每次采集一个不可变目录，保留原始产出，不覆盖。
- `当前/`：每个方向一份最新汇总，覆盖更新，方便直接取用最新结果。
- 追溯时先看当前区，需要历史或来路再进批次区查配方。

## 台账生成

用 `scripts/ledger.py` 从 items.jsonl 与 manifest.json 自动生成三份文件，不手写，避免遗漏字段。

## 台账自检

生成后逐项核对：

- 总台账批次数与实际批次目录数一致
- 每批明细行数 = 保留条数
- 每条明细的原文链接非空且域名属于登记的站点
- 每条明细的本地存档文件存在
- 配方.md 六段齐全
- 隐私字段列全部为空或已脱敏
